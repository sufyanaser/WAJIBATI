## ٢. قواعد هندسية عامة

1. عرض الهاتف مستقل بصرياً عن سطح المكتب، مع مشاركة مصدر البيانات ومنطق الأعمال.
2. منع التمرير الأفقي العام للصفحة، دون إخفاء محتوى متجاوز للعرض باستخدام `overflow: hidden` كحل تجميلي.
3. اعتماد مصدر حقيقة واحد لهوية المدرسة والإسنادات والجدول والواجبات.
4. مراعاة iPhone وAndroid WebView وسطح المكتب؛ دعم RTL وSafe Area وأهداف لمس لا تقل عن 44px حيث أمكن.
5. فصل قوالب الطباعة عن مكونات العرض التفاعلي.
6. لا تعديل إنتاجي لقاعدة Supabase، ولا دمج أو نشر دون تفويض صريح.

## ٣. المواصفات التفصيلية ومعايير القبول

### تعديل-١ — هوية المدرسة وبوابة الإدارة
- **المشكلة:** تشابه تسجيل دخول الإدارة وولي الأمر، وثبات معلومات المدرسة في عدة مواضع.
- **المطلوب:** تمييز بوابة الإدارة بصرياً؛ إعدادات مركزية للاسم والشعار والمحافظة والمديرية والعنوان، وتطبيقها على الواجهات والتقارير.
- **التنفيذ:** صلاحيات إدارية للتحرير، حالات تحميل وقيم افتراضية؛ لا حاجة إلى Multi-Tenant في هذه المرحلة.
- **القبول:** تعديل اسم المدرسة أو شعارها ينعكس في المواضع المعتمدة دون تعديل الشيفرة أو إضعاف المصادقة.

### تعديل-٢ — الهيكل العام لواجهة ولي الأمر
- **المشكلة:** تكرار عناصر التاريخ والأرشيف والتصدير وازدحام الترويسة.
- **المطلوب:** ترويسة مختصرة باسم الطالب والصف والشعبة؛ منتقي تاريخ واحد؛ شريط سفلي للأرشيف والتصدير والاستفسارات والخروج؛ نقطة تصدير واحدة بخيارَي PNG وPDF.
- **التنفيذ:** توحيد التنقل وحالة التاريخ المختار وإزالة التكرار.
- **القبول:** لا وظائف مكررة، مع الاحتفاظ بالتاريخ المختار عند التنقل.

### تعديل-٣ — مستند الواجبات اليومية A4
- **المشكلة:** توزيع غير ملائم للمساحات في التصدير، ومشكلات الترويسة والتذييل والتنبيهات والملاحظات.
- **المطلوب:** PDF بمقاس A4 عمودي، شعار واجباتي في الأعلى وشعار الرنين في الأسفل، وتاريخ واضح ومساحات مرنة للتنبيهات والملاحظات.
- **التنفيذ:** نموذج بيانات للطباعة منفصل عن الواجهة؛ استخدام HTML/CSS للطباعة أو مولّد PDF يحافظ على العربية وتعدد الصفحات. لا يُشترط DOCX وسيط إلا عند الحاجة إلى مستند قابل للتحرير.
- **القبول:** PDF غير فارغ وقابل للطباعة دون اقتطاع، مع اختبار النصوص القصيرة والطويلة وتعدد الصفحات.

### تعديل-٤ — الجدول الأسبوعي المرن وتصديره
- **المطلوب:** أيام وحصص وشعب قابلة للإدارة؛ إظهار المادة والمدرس ووقت الحصة؛ تصدير شامل A4 أفقي عند الملاءمة، وتصدير شعبة واحدة عمودياً.
- **التنفيذ:** الاستناد إلى بيانات `timetable` والإسنادات بعد التحقق من المخطط؛ قالب طباعة مستقل.
- **القبول:** نصوص مقروءة دون ضغط مخل؛ تاريخ ووقت التصدير الفعلي بتوقيت بغداد.

### تعديل-٥ — الأساس العام لتجاوب لوحة الإدارة
- **المشكلة:** تمرير أفقي، عناوين مقتطعة، وبطاقات وأزرار كبيرة وغير متسقة.
- **المطلوب:** ضبط الحاويات وGrid/Flex والترويسة ونظام المسافات والأزرار.
- **التنفيذ:** معالجة العنصر المسبب لتجاوز العرض؛ فحص `scrollWidth` عند 320 و375 و390 و430 و768 بكسل.
- **القبول:** لا تمرير أفقي عام ولا اقتطاع أو فراغات خارج الشاشة، مع سلامة سطح المكتب.

### تعديل-٦ — إسناد المدرسين والشعب
- **المشكلة:** جدول كثيف غير مناسب للهاتف.
- **المطلوب:** بطاقات مدرسين تعرض المادة وعدد الشعب وتفاصيل قابلة للتوسيع، مع جدول أكثر كثافة للكمبيوتر.
- **التنفيذ:** إعادة استخدام علاقات الإسناد الحالية؛ بحث وتصفية وترتيب دون تغيير قاعدة البيانات لمجرد تحسين العرض.
- **القبول:** العثور على المدرس ومعرفة إسناداته دون تمرير أفقي أو فقد سجلات.

### تعديل-٧ — إدخال الواجبات وحفظها ونشرها
- **المشكلة:** ازدحام عناصر اختيار الشعبة والتاريخ والحصص والإجراءات.
- **المطلوب:** شريط تحكم مختصر، بطاقات حصص منتظمة، حقول نصية مرنة، حالات حفظ ونشر واضحة.
- **التنفيذ:** حماية التغييرات غير المحفوظة؛ منع النشر غير المؤهل؛ عدم تغيير منطق النشر دون اختبار.
- **القبول:** حفظ ونشر صحيحان دون فقد بيانات أو نشر عرضي، مع إثبات وصول الواجب إلى ولي الأمر المخوّل.

### تعديل-٨ — عرض وتحرير الجدول الأسبوعي
- **المشكلة:** شبكة الجدول الواسعة غير مناسبة للهاتف.
- **المطلوب:** عرض يومي وبطاقات حصص على الهاتف، مع إبقاء الشبكة الكاملة للكمبيوتر.
- **التنفيذ:** مشاركة بيانات تعديل-٤ والتحقق من الإسناد والتعارض قبل الحفظ.
- **القبول:** تعديل حصة من الهاتف دون تمرير أفقي عام أو تعديل حصص أخرى خطأً.

### تعديل-٩ — التعميمات والتنبيهات
- **المشكلة:** نموذج طويل وبطاقات إشعارات مزدحمة.
- **المطلوب:** حقول واضحة للعنوان والمحتوى والنوع والجمهور وتاريخ الانتهاء؛ معاينة قبل النشر وبطاقات مختصرة.
- **التنفيذ:** فحص دورة حياة الإشعارات الحالية، وصلاحيات الاستهداف، وسلوك Push قبل أي تغيير.
- **القبول:** إنشاء وتعديل واستهداف صحيح دون إرسال إشعارات حقيقية أثناء اختبارات غير مصرح بها.

### تعديل-١٠ — مركز السجلات المدرسية
- **المشكلة:** تبويبات متعددة وأزرار مزدحمة وبطاقات ضخمة.
- **المطلوب:** اختيار قسم واضح على الهاتف، بحث متخصص، بطاقات مختصرة، ومسارات إضافة وتحرير واضحة.
- **التنفيذ:** المحافظة على CRUD والعلاقات؛ استيراد Excel مستقل مع معاينة وتحقق قبل التطبيق.
- **القبول:** بحث وتحرير دون تداخل، وحماية سلامة السجلات المرتبطة عند الحذف.

### تعديل-١١ — الإعدادات والصلاحيات
- **المشكلة:** جمع إعدادات المدرسة والحسابات وPIN وحالة النظام في صفحة طويلة.
- **المطلوب:** أقسام منفصلة لبيانات المدرسة، الحسابات والصلاحيات، أمان الحسابات، وحالة النظام.
- **التنفيذ:** مشاركة مصدر إعدادات تعديل-١؛ مراجعة وظيفة `reset-pin` وصلاحياتها وعدم إظهار أسرار.
- **القبول:** وصول واضح لكل وظيفة وإعادة تعيين PIN بصورة آمنة.

### تعديل-١٢ — القائمة الجانبية
- **المشكلة:** Drawer عريض وطويل على الهاتف، وفراغات زائدة وإغلاق غير واضح.
- **المطلوب:** قائمة من اليمين بترويسة مختصرة وروابط مرتبة وتمييز القسم النشط وحساب المستخدم والخروج أسفلها.
- **التنفيذ:** `100dvh` وSafe Area وإدارة التركيز وإغلاق القائمة عند التنقل أو الضغط خارجها ومنع تمرير الخلفية.
- **القبول:** الوصول لجميع العناصر دون تجاوز العرض أو حجب الخروج.

### تعديل-١٣ — شبكة المواد المختصرة لولي الأمر
- **المشكلة:** بطاقات الواجبات الطويلة تجعل الصفحة الرئيسية شديدة الامتداد.
- **المطلوب:** شبكة مواد/حصص مختصرة تعرض اسم المادة ورقم الحصة ومؤشر وجود واجب، مع فتح تفاصيل الحصة عند الضغط وزر رجوع واضح.
- **التنفيذ:** دعم الرجوع في المتصفح وAndroid، وإبقاء جميع النصوص والمرفقات في التفاصيل؛ عدم افتراض ست حصص ثابتة.
- **القبول:** ملاءمة الشبكة للشاشة قدر الإمكان مع تمرير احتياطي آمن للشاشات الصغيرة والخطوط المكبرة، وإظهار التفاصيل كاملة.

### تعديل-١٤ — المساحة المرئية والشريط السفلي
- **المشكلة:** الشريط السفلي الثابت يغطي محتوى الواجب الطويل.
- **المطلوب:** حجز مساحة للشريط السفلي، وفصل تمرير التفاصيل عن شبكة المواد.
- **التنفيذ:** `dvh` وSafe Area وتخطيط مرن، دون إخفاء التمرير على الصفحة بالكامل.
- **القبول:** الوصول إلى نهاية المحتوى وجميع الأزرار دون حجب.

### تعديل-١٥ — الأرشيف والاستفسارات
- **المشكلة:** أرشيف طويل يعيد عرض النصوص كاملة، وصفحة استفسارات غير منظمة بما يكفي.
- **المطلوب:** أرشيف بالتاريخ وشبكة مواد مختصرة تعيد استخدام تعديل-١٣؛ صفحة استفسارات تعرض بيانات الطالب والحساب تلقائياً ونموذجاً واضحاً.
- **قرار النطاق:** واجهة الاستفسارات فقط حالياً؛ **زر الإرسال معطل**. لا إنشاء جداول مراسلة أو ردود أو إشعارات جديدة، ولا إظهار نجاح وهمي. «استفساراتي» وحالات متابعة الطلبات مرحلة مستقبلية.
- **القبول:** أرشيف سهل التصفح، وصفحة استفسارات واضحة دون إرسال فعلي.

## ٦. بوابات الجودة (Gate)

- [ ] **Git:** فروع مستقلة، وعدم الكتابة فوق عمل الوكلاء الآخرين.
- [ ] **وظائف:** اختبارات المصادقة والحفظ والنشر والصلاحيات والبيانات.
- [ ] **تجاوب:** فحص شاشات الهاتف والكمبيوتر وعدم التمرير الأفقي العام.
- [ ] **قاعدة البيانات:** لا تعديل إنتاجي أو Migration دون تفويض.
- [ ] **Android:** الرجوع والتنقل والتصدير والجلسة داخل WebView.
- [ ] **طباعة:** PDF حقيقي بمقاس A4، بخطوط وشعارات وبيانات سليمة.
- [ ] **مراجعة بصرية:** صور قبل/بعد، RTL، مسافات، وأهداف لمس مناسبة.
- [ ] **نشر:** لا Push أو Merge أو Deploy دون موافقة صريحة.
